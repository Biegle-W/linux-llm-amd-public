# Local model hub: any model, started on demand — October 22, 2026

The user asked for one OpenAI-compatible endpoint through which DSH and network clients can
select **every model on this PC**, without anyone launching its backend by hand.

## How to use it

| Client | Endpoint | Auth |
|---|---|---|
| Local apps, scripts, DSH | `http://127.0.0.1:30100/v1` | none (loopback only) |
| LAN/Tailscale clients, Turnstone | the existing gateway on port 10000 | existing API key |

- `GET /v1/models` lists all enabled models with `backend`, `context_length`,
  `loaded` and `auto_start`.
- `POST /v1/chat/completions` (or `/v1/completions`) with any listed `model` works.
  Strata and Maya models support chat completions only.
- DSH's five local providers point at the hub; sending a message to a selected model starts it.
  Restart DSH once to pick up the new addresses. The DSH default stays Strata Q3.

## What happens on a request

1. **Backend already serving the model:** the request is forwarded at once.
2. **Otherwise:** the hub starts that backend headlessly with its normal guarded launcher
   (`dsh/start-backend-terminal`; Strata/Maya with `--no-browser`, Maya with the requested
   profile). The launcher's startup handover stops the previous backend, and every memory,
   VRAM, swap and thermal guard stays in place. Within a backend, its own router still switches
   between that backend's models.
3. **Another backend is still answering:** the switch waits until those replies finish.
   No answer is cut off.
4. **Streaming requests:** response headers are sent immediately, followed by SSE comment
   keep-alives (`: loading <model>`) every 10 s until the first token. OpenAI clients ignore
   comment lines.
5. **Failures** are returned with the launcher's own reason: HTTP 503 for non-streaming
   requests, or an SSE `error` event followed by `[DONE]`.
6. **`hardware/generated/GPU-LOCK` present:** the hub never starts or switches a backend
   (`gpu_reserved`). A backend that is already serving is still used.
   Agents testing GPUs keep holding the lock as before.

Since October24, managed backends unload after ten minutes of inference inactivity,
or switch when another backend is requested. Desktop shortcuts keep working;
the hub adopts whichever backend is serving.

## Ten-minute idle power saving — October24

The hub checks every five seconds and unloads the managed model/engine after
**600 seconds since the last inference request completes**. Each new backend
gets a full grace period. Hub/gateway/DSH, direct public router and original native
Chat POSTs count; health, model-list and status GET polling do not reset the clock.
Activity tracking also covers model loading and Maya's background model selector.

Requests hold a cross-process shared activity lock through loading/generation and
response completion. Idle shutdown needs the exclusive lock, the normal backend
startup lock and a short owned GPU-LOCK. It checks native running/queued requests
or llama.cpp slots and established backend connections, and defers on busy or
unknown state. An agent/daily-update GPU-LOCK always blocks idle unloading.
The shutdown callback uses only the existing configured inference ownership matcher
and worker cleanup, preserving DSH, gateway and unrelated applications/jobs.

The hub remains available with all 13 model IDs. The next inference request
restarts the normal guarded backend automatically. Backend-specific native pages
and terminals are served by their backend and may need reopening after shutdown;
DSH and gateway access remain available. No ports, model/profile/context/default,
runtime versions or memory guards change. `/health` reports `inflight`,
`idle_timeout_seconds` and `idle_state`; its GET does not count as inference activity.
Tracking timestamps/locks are private, ignored state under `dsh/data/inference-idle`.

Zero-swap validation concerns only managed inference processes/workers, never
the system's total swap usage. Background applications may use swap. Tests include
an unrelated process with a large swap allocation that leaves inference totals
unchanged. No global swap setting is changed.

CPU regressions cover the 600-second boundary, busy/stream/loading/queue safety,
unknown telemetry, startup/GPU locks, process cleanup and next-request restart.
Production activation preserved the already loaded backend and started a fresh
ten-minute grace period. The live Qwen27B/vLLM cycle observed shutdown at 607.0
seconds of inactivity (600-second threshold plus polling/cleanup/observation),
with zero remaining managed inference processes. Sampled whole-card memory fell
from 16.871 to 0.026 GiB per card; the existing DSH listener and gateway process
were preserved and all 13 catalog IDs remained available. Both repositories pass
86 CPU safety/frontend/accounting checks. Next-request reload is CPU-simulated;
other backends were not rerun on GPUs for this adapter change. These are functional
checks, not new throughput or measured-power claims. [Curated evidence](results/model-idle-2026-10-24.json).

## Components

- `dsh/model_hub.py`: the hub, run by the user service `local-llm-hub.service`
  (`network/local-llm-hub.service`, `KillMode=process`, so restarting the hub leaves a running
  backend alone).
- `dsh/model_catalog.py`: the single model catalog shared by the hub and the gateway.
- `network/gateway.py`: still authenticates LAN/Tailscale clients, then forwards to the hub
  instead of requiring a running backend.
- `dsh/configure_local.py`: DSH provider `baseURL`s now point at the hub.
- `dsh/inference_idle.py`: guarded 600-second idle watcher and shared request/load
  activity tracking, also used by the direct routers and native Chat adapters.

## Security

The hub listens on 127.0.0.1 only. As before, any local process can reach the loopback
backends. Network clients still need the gateway's API key and an allowed subnet. They can
now start and switch models, which the user explicitly requested. No new port is exposed
off-host.
