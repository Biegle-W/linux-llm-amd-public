# Nemotron Bolt Q4 replacement — October 18, 2026

The user requested replacing the active Nemotron 3.5 Bolt 74B-A9B 24GB IQ2
quant with Q4 while retaining CPU expert backing and genuine GPU expert caching
on both RX 7900 XTX cards. The installed host has 32 GB RAM; another 32 GB is pending.
Keep the API ID `nemotron-3.5-bolt`; no new model or frontend launcher is needed.
The existing llama.cpp backend and DSH/Turnstone/gateway catalogs select Q4.
Both Q4 shards must remain together in the `Q4_K_M` model subdirectory.

## Selected weights and runtime

- [Q4_K_M source](https://huggingface.co/darioooooo0o/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-GGUF),
  revision `b739f8c7c5484413ae3e55e6da8383f0f2570cee`.
- Two GGUF shards, **48,341,642,336 bytes / 45.02 GiB**, downloaded directly
  to the Shared SATA model drive. Both shard SHA256 values matched their
  pinned Hugging Face LFS records before activation. Weights never enter Git.
- Standard Q4_K_M is a mixed quant: metadata records Q4_K, Q6_K, Q8_0 and F32
  tensors. Architecture `nemotron_h_moe`, 88 blocks and 496 experts; 1M source
  context metadata does not establish a locally usable 1M context.
- Retained llama.cpp HIP revision `f12aaa344c971556ec35be054d7aac1d901fd510`;
  ROCm0/ROCm1, layer split 21:19, Q8_0 K/V, flash attention, one request,
  batch/microbatch 512/128, speculation off. Dense models remain on Vulkan.

## Selected memory placement

The selected profile uses 12 expert-bearing layers spread across the model:
`1,10,19,28,37,45,50,59,67,76,81,85`.
Their exact expert tensor bytes total **13,673,005,056 bytes / 12.73 GiB**.
The GPU expert-cache ceiling is **7,168 MiB total**, divided across both cards
in the 21:19 ratio. Actual allocation is bounded by the host-expert sets.
The retained context allocation is 262,144 tokens; actual retrieval was validated
at approximately 64K, not the full window.

The CPU copy and cached GPU copy both consume memory. Cache misses upload expert
weights for GPU computation; this is not CPU expert computation or free VRAM.
A higher quant can increase transfer/compute cost, so no speed gain is assumed.
Keep the existing scoped low-RAM, owned-swap and dedicated-VRAM-spill guards.

## Validation

Both files downloaded and SHA256-verified. The first 18-layer/15 GiB-cache
startup was stopped by the local 23 GiB-per-card guard at 23.84 GiB on GPU1
during workspace allocation. There was no VRAM spill; minimum available RAM
was 8.97 GiB. Two 18-layer/12 GiB-cache attempts hit the owned-swap guard before
generation, including a retry matching production's disabled auto-fit pass.
Available system RAM remained above 9 GiB, so these controlled stops do not
prove an upstream OOM or a hard model-capacity limit.

The lighter 12-layer/8 GiB-cache startup reached model-ready with zero swap/spill,
but briefly reached 23.06 GiB on GPU0 and was stopped by the guard. The selected
12-layer/7 GiB-cache profile keeps the same strict memory guards.
The selected profile **passed arithmetic, JSON, a complete tool-call/result
round trip and three-marker retrieval with 63,911 input tokens**. Full 256K
filling/quality and sustained long-context decode remain untested.

| Quant / placement | Context allocated | Short code decode t/s | ~64K prefill t/s | Minimum available RAM GiB | Peak VRAM GiB |
|---|---:|---:|---:|---:|---|
| Q4_K_M, 12 CPU expert layers, 7 GiB cache | 262,144 | 35.7 (101 tokens) | 424.0 | 13.60 | 22.75 / 22.82 |
| Retired 24GB IQ2, 20 CPU expert layers, ~7.85 GiB actual cache | 262,144 | 40.7 (87 tokens) | 526.4 | 16.29 | Historical record |

Single functional probes, not repeated benchmark medians or a matched quality/
speed comparison; short output lengths may differ. Q4 worker swap peaked at
0.00 MiB and dedicated VRAM spill at 0.00 MiB. The expert cache was partially
warmed by the short checks before the uncached long prompt. Retrieval took
151.4 seconds; its short answer does not establish sustained decode at 64K. [Curated result and checksums](nemotron-q4-2026-10-18.json).

## Managed activation and retirement

The normal visible-terminal llama.cpp launcher loaded Q4 through the authenticated
gateway and returned the correct arithmetic answer. All eight gateway profiles
remain registered; DSH and Turnstone catalogs were refreshed without changing
valid saved frontend selections. The API ID and connection addresses are unchanged.
The Q4 backend is left running in its visible terminal.

After that managed check passed, the old 22,018,326,528-byte IQ2 model and its
obsolete installation directory were removed (20.51 GiB). Its public source
revision/checksums and historical benchmarks remain recorded for recovery.
Both Q4 shards remain together on Shared SATA; no shortcut or NVMe model copy
was created. Config/memory tests passed in both repositories: 11 memory-policy,
2 DSH catalog and 6 FreeToken CLI tests.

## NVIDIA FreeToken removal in the same task

Removed the incompatible system package `free-token-desktop` `0.2.0-beta.23`,
its legacy CUDA engine directory (15.24 GiB of files) and old `ft` symlink at the
user's explicit request. The independent `ft-rocm` ROCm build and tested Qwen
profile remained installed at that point. A later user request removed all
FreeToken software, launchers, caches and saved app data; see the
[retirement report](FREETOKEN-RETIRED-2026-10-18.md). Production
ROCm/vLLM/SGLang/llama.cpp environments and historical NVIDIA reference records
were not removed.
