# Maya v1.1.19 and ROCm 10 evaluation — October 20, 2026

Maya **v1.1.19 /3384b5e** is promoted on **ROCm7.2.3** after native and normal
Desktop/Ptyxis, original Chat/Monitor, authenticated gateway and GLM→DeepSeek→GLM
checks. Both existing Maya-S packs remain on the new shared NVMe. ROCm10 is
**rejected for Maya**; the already-tuned7 stack is faster and the10 fallback
stalled. No other production engine or system driver is migrated.
[Full numerical evidence](results/maya-rocm10-2026-10-20.json) retains every
trial, failed arm, source/binary fingerprints, actual lengths and thermals.

## Correctness, settings and method

The host-loopback encoder/server unit suite passed336 tests,10 skipped. The initial
sandbox-only socket errors were an execution restriction, not an engine failure;
the actual-host rerun passed. Fourteen core GLM/HIP/device/MMQ checks passed
independently on each physical GPU with each SDK. The optional focused upstream
hipBLASLt test expects different BF16/F16 shapes; its missing-table skip is not
counted as a GLM table accuracy pass. The LLVM/lld test-only missing prefill link
dependency was supplied by an external CMake overlay; engine source is unchanged.

The new default DeepSeek Q8_K rounding fails the synthetic reversed
IQ3_S/IQ2_S token/window CPU-reference checks with both SDKs. The actual downloaded
model's expert gate/down pairs are IQ2_S/IQ3_S, IQ2_XXS/IQ3_XXS and MXFP4/MXFP4;
the reversed pair is absent. Candidates conservatively retain previous-production
rounding explicitly with `DS4_IQ_Q8K=0`, without weakening any tolerance. Under
that compatibility setting the ROCm10 broad suite passes; ROCm7 retains only the
two historically excluded mixed IQ4_XS/Q4_K and Q4_K/IQ4_XS bit-exact failures.
No support for untested/failing formats is inferred.

All model arms retain both GPUs,32,768 total context, unchanged quants,
GLM40GiB expert RAM/MTP and DeepSeek24threads/noDSpark. Every arm starts with its
own byte-identical copy of the production expert seed; production seeds/configs
are fingerprinted before/after. Native8GiB targets, actual>=6GiB/card loaded
startup admission, continuous latched3GiB/hard1.5GiB floors,52G/no-swap worker
scope and zero owned swap/spill remain. Only owned workers are stopped.

Three timed code/prose trials use the shared256-output-cap method, excluding a
warmup for each task. Three fresh salted prefill requests use a64-output cap;
~8K Qwen-token prompts have different actual Maya tokenizer counts, retained per
trial. Native prefill is distinct from external SSE TTFT and decode. Fresh cache
counts must be zero. Functional checks cover arithmetic, JSON, synthetic tool
roundtrip and SSE; selected candidate checks also cover fresh near32K retrieval
and full-history follow-up. No real external tool is executed.

The ROCm10 speed gate was declared before timing: compared with the same new
Maya source on7.2.3, geometric mean of code/prose/native-prefill ratios must
exceed1.03 and every individual speed must be>=0.95, with all functional,
context, memory and normal launcher/UI/authenticated gateway gates passing.
Borderline results require a repeated matching pair, not selected reruns.
Three samples do not establish statistical significance or a universal speedup.
The separate no-table10 arm distinguishes tuning-table benefit from whole-SDK
migration. A lower admission threshold or different renderer is not a speed gain.

New DeepSeek exact long-prompt skipping requires all trunk layers on one GPU;
retained dual-layer groups may not qualify. Quality-changing skip mode2 and a
single-card fallback are not enabled. The new reference encoder/license and
jsonschema dependency are retained; Responses/background unit tests are not a
claim of new remote gateway exposure.

## Expert residency and adaptive state

The new7 GLM native diagnostic counters for the three code trials report
10.02–10.89 disk expert reads/token,27.08–30.00ms/token disk-wait counters,
and64.92–67.47% VRAM hits. Prose reports9.53–10.14 reads/token and
23.78–25.93ms/token disk-wait counters. The CPU lane also performs expert
work. These aggregate per-device/CPU/I/O counters overlap; do not add them
to reconstruct wall time or attribute the entire community gap to SSD access.
Counters and exact three-trial MTP acceptance are preserved numerically.

New DeepSeek automatically calibrates its PCIe expert lane and persists a small
`lane-times.txt` sidecar. This is not a weight modification. Its key includes
engine version/build timestamp, pack, bus/GPU and expert format, so separately
compiledSDK7/10 do not inherit one another's calibration. The7 arm was already
running with the upstream pack-side default when identified; its sidecar snapshot
is retained privately. The10 arm redirects `DS4_LANE_CAL` to its experiment
directory before its first start. No descriptor/index/Engram or GGUF is rewritten.
Production now explicitly uses `DS4_STREAM=0`; that mode returns before lane calibration, so no active calibration sidecar is required. The experimental automatic-lane sidecar is preserved privately; it is not shared across Windows/Linux or SDK builds.

The automatic-stream10 arm emitted a device-pull completion-not-observed warning.

automatic-stream arms and their warnings remain visible; the SDK speed gate is
unchanged. Implementation: [pinned lane policy](https://github.com/mw00/project-maya/blob/3384b5e9366e696e5f23f51772fb94a8a7948e41/src/ds4/ds4_model.cu#L5914-L6070).
