loading is excluded. These bounded smokes do not establish full agent/science

## Activation and Desktop web shortcut — October 21

The user chose **profile only**: Sage is a normal llama.cpp profile for DSH,
Turnstone and API clients. The Agents-A1 research harness, its Serper/Jina
accounts and its Docker/SandboxFusion sandbox are **not** installed. The profile
`sage-a1.5` (`dsh/models-hip.ini`, `models.json`, `llama-runtime.json`,
`moe-offload.json`) is Codex's validated SDK7/MTP3/64K configuration plus the
vision projector, so it is now the eleventh active llama.cpp profile. With the
projector at 64K, Codex's vision run kept at least 11.1/12.5 GiB free per card.
Later on October 21 the user set the DSH default to Strata Q3; see AGENTS.md.

The **Sage** Desktop shortcut follows the web-app rule. It opens a visible
terminal running `dsh/start-sage`, which runs the normal guarded llama.cpp launcher with
`--chat-model sage-a1.5`. After the router is healthy, the launcher
requests `POST /models/load` through the router, so memory admission and HIP
runtime selection still apply. It then waits for `loaded` and opens llama.cpp's built-in
Chat at `http://127.0.0.1:8080/#/?model=sage-a1.5`, with Sage preselected.
`--no-browser`, or a session without a display, loads Sage without opening a browser.
Ctrl+C or closing the terminal stops the backend.

Router changes needed by the built-in Chat:
- Pass through gzip encoding. The UI is served gzip-only.
- Do not hold the request lock for the long-lived `/models/sse` stream.
- Add an `unloaded` status for inactive-runtime profiles.
- Proxy the model-less resumable-stream lookup.
- Force `autoload=false` on proxied GETs that name a model, so the UI cannot bypass
  the admitted POST load path.

- Non-streaming gzip and streaming API answers.
- Correct image answer through the router.
- Actual Desktop launch through `gio launch`, with Chrome opened after readiness.
