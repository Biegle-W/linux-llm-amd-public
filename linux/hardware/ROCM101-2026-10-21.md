## Preparation and compatibility limits

Native builds use Clang24.0git, gfx1100 and SDK-provided rocWMMA2.2.1 headers;
controls use their retained compiler/rocWMMA2.2.0 builds. The initial Maya all-target
build missed test-only prefill/hipBLASLt link dependencies under the new linker.
An external CMake overlay fixed test-executable linking; engine source is unchanged.
All14 core/GLM tests passed separately on both cards. DeepSeek's default rounding
failed the known reversed-pair checks; the retained `DS4_IQ_Q8K=0` path passed the
broad suite on each card. Failed/untested formats remain disabled.

Framework candidates retain the existing engine sources, RDNA repairs and
compiled engine extensions, with official10.1 Torch/Triton/SDK packages. These
are compatibility-tested AOT extensions, not a claim that every extension was
rebuilt. Matching RCCL2.30.7 passed two-rank all-reduce/broadcast with retained
host transport (`NCCL_P2P_DISABLE=1`, SDMA disabled, Simple protocol). Controls
retain their previous RCCL. No direct-P2P capability is added by this test.

The first framework preflight mixed two COMGR/LLVM copies and aborted before
model loading. Candidate wrappers now use only the matching packaged wheel SDK;
the standalone native tarball is used by the C++ builds. Preparation failures
are preserved separately from measured inference. Candidate graphics audio import
and resampling pass with Torch2.14/TorchVision0.29a0/TorchAudio2.11.0.3, all AMD10.1
builds; a successful import alone is not workflow validation.

Graphics gate, fixed before graphics runs: each workflow's median server execution
must improve by over3%; median external elapsed must not regress over5%; actual
image/video/audio outputs, frame dimensions/counts and both-GPU/memory gates must
pass. A gain under10% requires a reverse-order repeat. This prevents a faster image
result from masking a slower or broken video workflow.

The inactive [test-link overlay](experiments/maya-rocm101-test-links.cmake) preserves
the Maya test-build repair for reproduction. Use it only with the pinned source
in a separate build through `CMAKE_PROJECT_INCLUDE`; it is not loaded by normal
launchers. The numerical record includes selected CMake flags and binary hashes.
Official wheel index used: `https://stable.repo.amd.com/rocm/whl-next/`.

Comfy's retained Torch reports packaged ROCm7.2.1, unlike the native7.2.3 SDK
used by the LLM controls. Its normal launcher does not source the LLM SDK wrapper.
The comparison records the actual loaded libraries. Legacy helper names such as
`strata-rocm10` and `llama-sdk10` refer to this new10.1 experiment, not the earlier
10.0 experiment; the numerical record labels the tested stack explicitly.

The initial vLLM code answer is identical by output hash across stacks; the prose
answer differs. Three repeated timings of one answer do not establish broad
workload gains. In addition to the reverse-order pair, confirmation therefore
uses seeds42/43/44 at the same prompts/settings and applies the same speed gates.
All output counts/hashes are retained; no answer text is published. SGLang's
sampled answers vary even within a stack, which also limits single-prompt claims.

Strata scope is the maintained Q3 DSH/API backend with its original local frontend.
The separately packaged AppImage and its inactive standalone inference preset
are unchanged. Comfy compares the shared backend used by browser and official
Desktop; the native desktop shell itself is not a ROCm build.

The vLLM history follow-up does not report cache-token usage in its API response.
The old helper defaults that missing field to0; it is not a measured cache count.
Dividing the entire160,913-token history by the1.229s follow-up phase would falsely
suggest130,962t/s uncached prefill. The curated record explicitly marks that
ratio invalid for throughput reporting. The measured follow-up TTFT1.388s,
total1.998s and correct markers are retained separately. Fresh salted requests
and history reuse remain distinct workloads; missing cache metadata is not
backfilled.
