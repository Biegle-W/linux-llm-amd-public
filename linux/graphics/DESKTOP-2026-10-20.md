## Reproduce

1. Download the official Linux package; verify its version and record its hash.
   Keep downloaded packages under ignored `runtime/comfy-desktop/`; install the
   official `.deb` through APT so Ubuntu receives its sandbox profile.
2. With Desktop closed, run `python3 graphics/configure-comfy-desktop.py`.
   It preserves unrelated app records and imports the existing environment.
3. Install `graphics/comfy-desktop` into the user's PATH. Adjust absolute paths
   in `launchers/comfyui-desktop-2.desktop`, install it into the user's applications folder,
   and refresh the desktop database. The native menu uses the package-provided
   `comfyui-desktop-2` icon; the browser shortcut keeps the official frontend SVG.
4. From the app menu open **Comfy Desktop**, or use the **ComfyUI** browser
   shortcut on Desktop, and choose **Workflows** → **Qwen-Image 2.1 BF16** or
   **MiniMax H3 INT8**. Existing [workflow instructions](INSTALL.md) still apply.

The user's October21 standing rule places web interfaces on Desktop and native
apps in the application menu. Accordingly, Desktop **ComfyUI** uses the existing
visible-terminal/browser launcher; menu **Comfy Desktop** uses the official app.
DSH, Turnstone, managed Strata Q3 and Maya browser entries stay on Desktop and
are hidden in menu templates. Native Strata App and Unsloth remain in the menu;
backend-only terminal and hardware-control shortcuts are preserved.

The browser-only `ComfyUI.desktop` menu entry remains hidden; the managed
`comfyui-desktop-2.desktop` overrides the package entry to avoid duplicates.
[Numeric integration checks](desktop-validation-2026-10-20.json) contain no private paths.

App registration/settings, media, logs, package and extracted binaries stay
excluded from both repositories. Public setup uses example paths; Windows uses
its own app/runtime and corresponding Shared model path.

## Dock/window identity correction — October 21

The user reported that the editor appeared under a separate/missing-logo dock
icon. Live, temporary Wayland protocol diagnostics showed the window advertising
`app_id="Comfy Desktop"`. Our managed menu override omitted the official package's
`StartupWMClass=Comfy Desktop`, so it lacked the matching identity hint. Restore
that field and use `Icon=comfyui-desktop-2`, the native package's installed icon
name, rather than the browser frontend SVG. No Comfy favorite/pinned entry was
present to replace; unrelated favorites were left intact.

The [desktop-entry specification](https://specifications.freedesktop.org/desktop-entry/latest/recognized-keys.html)
defines `StartupWMClass` window matching and icon-theme lookup. The official
Debian desktop entry supplies the matching class; its 512px packaged PNG has
local SHA256 `9fd848dccce0c50f2acc597e734cf3ef71cfd538540379aa3c6ac283b7101d8e`.
This asset is resolved from the package's hicolor theme; it is not copied into Git.

The observed Wayland ID equals the installed launcher's matching field. Gio
resolves the correct app record/icon, installed/source entries match and desktop
syntax passes. The idle diagnostic instance was closed and the normal app reopened
with no Wayland debug environment. Both GPUs and saved workflows remain available.
GNOME disallows direct app/window introspection over D-Bus, so these checks verify
protocol identity/metadata/icon resolution rather than an automated visual dock
inspection. The native app remains open. Models, workflows, inference settings,
sandboxing and the Desktop-web/menu-native placement rule are unchanged.
