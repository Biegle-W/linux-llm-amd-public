# FLUX 3 Image Klein on the RX 7900 XTX — October 23, 2026

At the user's request, the official ComfyUI release of FLUX 3 Image Klein was downloaded, added to
ComfyUI and tested with one text-to-image generation and one single-reference edit. Both passed.

## Model and files

[black-forest-labs/flux-3-image-klein-comfy](https://huggingface.co/black-forest-labs/flux-3-image-klein-comfy),
revision `feef60b0aaf63a4773ace96636ebbcf43b881312`. Gated under the FLUX Kommunity License
(non-commercial use, plus a commercial-output exception for qualifying users); the user accepted
it and logged this PC in to Hugging Face. 5.6B image transformer; one model does text-to-image,
editing and up to 10 reference images ([BFL announcement](https://bfl.ai/blog/flux-3-image-klein)).

an upsampler: it expects full scene captions.

## Workflows

- `workflows/flux3-klein/`: the official BF16 text-to-image, edit and multi-reference UI
  workflows (MIT, `LICENSE.upstream`). Drag one onto the ComfyUI canvas. They reference the BF16
  upsampler; select `qwen3.5_9b_flux3_prompt_upsampler_int8_convrot.safetensors` instead. The
  sample `klein_ref_*.jpg` images were copied to ComfyUI's `input/`.
- `workflows/build-flux3-klein-api.py` builds API graphs from those files, reading the upsampler
  system prompts and sampler settings from them. It keeps the no-bounding-box path and places the
  denoiser on GPU 0 and the upsampler, encoder and VAE on GPU 1 (`GraphicsCLIPLoader` now
  accepts `flux3`). Sampler: Euler, simple, 16 steps, CFG 1.0, flux shift log(16).
- `workflows/flux3-klein-{t2i,i2i}-api.json`: the two test graphs, run with `run-workflow.py`.

## ROCm crash and workaround

The first edit attempt crashed ComfyUI (segmentation fault, then `std::bad_variant_access` and
heap corruption in repeats). Text-to-image was unaffected because only edits send an image to
the upsampler's Qwen3-VL vision tower.

Cause: in torch `2.15.0.dev20260827+rocm7.2`, `conv3d` **with a bias** aborts on the GPU when
MIOpen is disabled (bf16 and fp32; reproduced in plain PyTorch with nothing else loaded).
ComfyUI disables MIOpen on AMD by default (`torch.backends.cudnn.enabled = False`, opt-out
`COMFYUI_ENABLE_MIOPEN=1`). The vision patch embedding is exactly such a convolution
(kernel = stride = 2×16×16, with bias). The same call with MIOpen enabled works and matches the
CPU result. The BF16 Qwen3-VL-4B encoder's vision tower fails the same way, so this affects any
Qwen3-VL image input in this ComfyUI build, not only the int8 upsampler.

Fix: `comfyui-device-loaders/__init__.py` (installed by `start-comfyui` on every start) routes
only patchify `Conv3d` calls (kernel = stride, with bias, on ROCm, MIOpen off) through MIOpen.
Other convolutions, including the Qwen-Image and H3 VAEs, keep ComfyUI's default path; MIOpen
was not enabled globally because that would change the validated VAE path. Remove the workaround
once the PyTorch nightly is updated and the bias case passes without MIOpen. Not re-run after this
change: the Qwen-Image and H3 workflows. Their VAE convolutions do not match the patchify
condition, so they keep the previous path.
